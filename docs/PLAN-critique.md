# Plan critique (adversarial review, 22 Oct 2026)

Apply these when building. Severity in brackets.

1. [blocking] **Problem:** Safety hole: the meeting guard runs only when a surface is about to appear (F14 returns allow/defer before show). If a meeting starts while an overlay, the gate or the exam is already on screen (an unscheduled Teams call comes in, the learner unlocks the Mac to answer a call), nothing closes the surface. The gate's only exits are then Emergency skip (-20 Vitality) or the 5-minute timeout (-10), so the learner pays for answering a work call. A .screenSaver-level poster may also cover the incoming-call banner [unverified]. No test in §5.3 covers this case.
   **Fix:** In F14/§5.2, have IntrusionCoordinator subscribe to every signal stream for as long as any surface is visible. Any defer signal (mic, camera, meeting app, calendar, Focus) closes the overlay or gate within 1 s, logs outcome `deferredMidway`, costs nothing, refunds any penalty already applied, and puts the item back in the queue. An open exam pauses, which F5 already specifies. Put a free 'Joining a call' button on the gate itself, not only on overlays. In poster mode, leave the top-right notification area uncovered. Add tests `SafetyTests/meetingSignalWhileVisibleClosesFree` and `GateTests/callDuringGateRefunds`.

2. [high] **Problem:** The mic signal is unattributed and will defer every intrusion all day. Both F14 and the existing `SignalProbes.microphoneRunning()` use `kAudioDevicePropertyDeviceIsRunningSomewhere` on the default input, and any defer signal blocks every surface. Anything that keeps an input stream open makes overlays and the gate never fire, and the learner cannot tell why: a wake-word voice assistant, Discord voice, a browser tab with mic access, or Tenaz's own speaking module. The cue never shows up and the app looks broken.
   **Fix:** Replace the device-level check with per-process attribution. Enumerate `kAudioHardwarePropertyProcessObjectList`, and for each process read `kAudioProcessPropertyIsRunningInput` and `kAudioProcessPropertyBundleID` (both confirmed in the MacOSX26 SDK AudioHardware.h; https://developer.apple.com/documentation/coreaudio/kaudioprocesspropertyisrunninginput). Exclude Tenaz and a user allowlist (`Content/meeting-apps.json` gets an `ignoreMicHolders` list). Defer only when the holder is a meeting app, a browser, or unknown. Log the holder bundle ids in `intrusion_log`. Keep the device-level check only as a fallback when the process list API errors. Show the current holder in `--tenaz-probe-guard`. Add test `SafetyTests/micSignalIgnoresAllowlistedHolder`.

3. [high] **Problem:** The display-sleep assertion signal is also unattributed. `SignalProbes.otherAppPreventsDisplaySleep` returns true for any process holding PreventUserIdleDisplaySleep/NoDisplaySleep unless the assertion name contains 'useractivity'. A YouTube tab in a browser, Spotify video or `caffeinate -d` therefore reads as 'presenting'. Those fun-app moments are exactly when the learner wants to be interrupted, so the app goes quiet when it is most needed.
   **Fix:** Map each assertion's pid to a bundle id with `NSRunningApplication(processIdentifier:)`. Defer the poster or gate only if the holder is a meeting or presentation app (Keynote, PowerPoint, Zoom, Teams) or a browser that is also using the camera or mic. Treat any other holder as 'media playing', which allows sticker mode. Tivra's `capture_tick.mediaAssertionBundleId` shows attribution is feasible. Add test `SafetyTests/videoAssertionAllowsSticker`.

4. [high] **Problem:** The rule 'meeting/presentation app frontmost ⇒ defer' (F14 table: Teams, Slack, Webex, ...) is too broad. Teams and Slack are chat apps many people keep open all workday. With this rule Tenaz stays silent through the whole work window, which contradicts 'VERY intrusive'. Real calls are already caught by mic, camera, calendar and attributed assertions.
   **Fix:** In F14, split the meeting-app list into `callApps` and `chatApps`. Teams, Slack or Zoom frontmost with no mic, camera or calendar signal allows sticker mode only (no sound, no poster, no gate). Poster, gate and exam defer only on a hard signal (mic or camera attributed to that app, a calendar event, a presentation assertion). Keep 'I'm in a meeting' as the manual override. Add test `SafetyTests/chatAppFrontmostAllowsStickerOnly`.

5. [high] **Problem:** Anti-cheat misses the AI built into the text field itself. The gate and Exam Mode block paste, drag and Services, but leave on Apple Writing Tools (Rewrite/Proofread inside any NSTextView), macOS 14+ inline predictive text (which proposes English completions as the learner types), autocorrect, grammar check and text completion. That is AI help inside Tenaz's own field. It also undermines the retrieval the overlays depend on (typed recall turns into accepting a suggestion).
   **Fix:** In the custom NSTextView used by AnswerField, GatePanel and ExamPanel (F1, F2, F5 §3), set `writingToolsBehavior = .none` (macOS 15+; https://developer.apple.com/documentation/appkit/nstextview/writingtoolsbehavior), `inlinePredictionType = .no` (macOS 14+; https://developer.apple.com/documentation/appkit/nstextview/inlinepredictiontype), and set `isAutomaticSpellingCorrectionEnabled`, `isContinuousSpellCheckingEnabled`, `isGrammarCheckingEnabled`, `isAutomaticTextCompletionEnabled`, `isAutomaticTextReplacementEnabled` and `isAutomaticQuoteSubstitutionEnabled` to false. Remove the Writing Tools, Spelling and Substitutions items from the panel's context menu. Both properties were confirmed in the MacOSX26 SDK NSTextView.h. Add test `GateTests/answerFieldDisablesSystemAI`, which asserts all of these properties.

6. [high] **Problem:** The exam deny-list misses the learner's real cheating paths. Ruling 10 / §4.7 lists only the Claude desktop, ChatGPT (`com.openai.codex`) and Gemini apps. Research 05 §6 also flagged terminals, because developers run coding agents there, and the plan dropped them. Typical developer machines also have Ghostty `com.mitchellh.ghostty`, Terminal `com.apple.Terminal`, Raycast `com.raycast.macos` (Raycast AI), and AI-enabled browsers whose built-in chat is not a claude.ai or chatgpt.com URL, so Tivra's `window_focus` domains cannot see it [unverified]. A deny-list will always lag behind new AI tools.
   **Fix:** In F5 Exam Mode, switch from a deny-list to an allowlist. During a section the only allowed frontmost app is Tenaz. Meeting apps with a hard signal pause the exam instead of flagging it. Any terminal, browser, Raycast or other app frontmost for 3 s or more is a VIOLATION; 1-3 s is a WARNING; each one is hidden with `NSRunningApplication.hide()` and logged. Keep `denylist.json` only for the Tivra post-hoc scan, and add `com.mitchellh.ghostty`, `com.apple.Terminal`, `com.raycast.macos`, `company.thebrowser.dia` (whole-app), the Codex CLI and Claude Code processes (detect `claude` and `codex` child processes with `NSWorkspace.runningApplications` plus `ps`). The copy should say 'during exams only Tenaz may be in front'. Add tests `ExamTests/anyNonTenazAppFlags` and `ExamTests/meetingAppPausesNotFlags`.

7. [high] **Problem:** The product the learner asked for (very intrusive, punishment) never arms itself. Overlays, the gate and every penalty ship off. Onboarding (M9) says 'intrusions explained and left off, contract left empty'. Enabling needs calendar access, and every Contract change waits 24 h. An ADHD user who has to go back into Settings later to switch the core feature on will usually never do it, so by week 3 Tenaz is Anki with a mascot. Also, the 24 h delay applies to every change, which turns the commitment device upside down: it should slow loosening, not tightening.
   **Fix:** Keep DECISIONS rule 2 (shipping defaults stay off). Add a final onboarding step, 'Arm Tenaz', that shows a recommended preset (sticker overlays 4 a day, then poster after week 1; gate once a day; response cost on; repair task on), lists every escape hatch, and requires an explicit confirmation by typing 'I choose this'. Make the delay in F10 asymmetric: tightening takes effect at the next 04:00 boundary, loosening waits 24 h, and the kill switch stays instant. Move this step into M7 (the first build where overlay + gate exist) so it is not stuck in M9. Add tests `OnboardingTests/armRequiresExplicitConfirm` and `SafetyTests/contractLoosenDelayedTightenNextDay`.

8. [high] **Problem:** The free escapes are easier than the priced ones, so the commitment device leaks. The kill switch (dismiss everything until 04:00, no penalty), 'Pause intrusions 1 h' in the popover, and 'I'm in a meeting' (defer 60 min) are free and unlimited. Only Esc (-3) and Emergency skip (-20) cost anything. Someone who says the learner cheats will learn within a week that 'I'm in a meeting' is the free skip. Safety requires these to always work, not to be free with no trace.
   **Fix:** Keep every hatch instant and always working (§5.2). Make them honest instead: 'I'm in a meeting' is free when any meeting signal or calendar event corroborates it, and also free twice a day uncorroborated; after that it still works but counts as a skip (-3) and is logged as `meetingClaimUncorroborated`. The kill switch and 'Pause 1 h' stay penalty-free, but that day cannot be a qualified streak day unless the minimum is done in-app, and the weekly review (F16) shows the counts. Two or more kill-switch uses in a week trigger a contract-renegotiation prompt rather than a penalty. Add test `SafetyTests/hatchesAlwaysWorkButAreCounted`.

9. [high] **Problem:** The overlay takes keystrokes the learner meant for another app. The main trigger is 'app switch after 25+ min of work', so the panel appears about 20 s after the learner has switched apps, which is often while the learner is typing a Slack message, a commit or a password. `canBecomeKey` plus focus already in the answer field means those keystrokes, and a Return, land in the overlay and get graded as a wrong answer (red border, Spirit -3, relearning). Being punished for an error the app caused leads to uninstalling.
   **Fix:** In F1/M6, show the panel only after 2 s or more with no keyDown (`CGEventSource.secondsSinceLastEventType(.combinedSessionState, .keyDown)`). Keep the field inert for the first 600 ms after showing. Discard input received in that window, and never accept Return as a submit within 1 s of showing. Answers typed with no prior hint are never penalized when the panel appeared while the learner was typing. Add tests `OverlayTests/waitsForTypingPause` and `OverlayTests/earlyKeystrokesIgnored`.

10. [medium] **Problem:** Gate timeout penalizes being away from the desk. F2 charges -10 Vitality when the gate times out after 5 minutes. With Touch ID or Apple Watch auto-unlock the learner can unlock and walk away (a colleague, the phone), so the learner is punished for being absent. That penalty is not self-chosen and feels arbitrary.
   **Fix:** In F2/M7, if there was no keystroke in the gate and the user has been idle for the whole 5 minutes, close it free with outcome `timeoutIdle`, and re-offer it at the next qualifying unlock (still at most 3 a day). Charge -10 only for `timeoutAbandoned`, which means the learner typed into the gate and then used another app over it. Add test `GateTests/idleTimeoutIsFree`.

11. [medium] **Problem:** The mascot has a dead zone that runs straight through week 3. Placement grants stage 3 on day 1. Stage 4 then needs 400 mastered notes (FSRS stability of 21 days or more) plus 6 weeks and band 4.0 on two Monthly Mocks. There is also an internal mismatch: the new-card cap is 5 cards a day, but each note produces up to 6 sibling cards and siblings are buried, while the gates count mastered notes. Real note intake is about 1-3 a day, so 400 mastered notes takes 4-6 months. Ruling 7's '35 new items a week' assumes one card per note. Tena does not visibly change for months, which defeats 'a mascot that grows with the learner'.
   **Fix:** Define the new-card budget per note in F3 (introducing a note counts as 1, siblings unlock without spending budget), or count 'mastered' on the note's primary C/L card. Recompute the defaults in `stages.json`: stage 4 at 150 mastered and 4 weeks. Add visible micro-growth that never regresses (size, gill length, spots) every 25 mastered notes and at each qualified week, plus a cosmetic at weeks 2/4/8/12 (R15). Add test `MascotTests/microGrowthEvery25Mastered` and a simulation test that a learner doing 5 new cards a day reaches stage 4 within 10 weeks.

12. [medium] **Problem:** The one concrete punishment the learner named, blocking fun apps until the reviews are done, is pushed to Tivra patch P1, which may never ship. That leaves only mild Vitality loss. A read-only version is possible today: Tenaz already watches the frontmost app (`didActivateApplicationNotification`), and Tivra's classification shows what the learner treats as `social`.
   **Fix:** Add an F10 rule called 'Fun-app speed bump' (off by default, Contract, capped). After a deadline the learner chooses (for example 20:00), if today's minimum is not done and a fun app is frontmost, Tenaz shows the 3-item sticker overlay over it. Fun apps are a list in `Content/funapps.json` seeded from Tivra's read-only `social` rules, plus YouTube/Discord/Steam bundle ids. The sticker comes back at most every 10 minutes until the minimum is done. It never hides or quits the app, never fires on a meeting signal, and respects the daily caps. This counts as an intrusion, not a lock. Add test `PenaltyTests/funAppBumpNeverDuringMeeting`.

13. [medium] **Problem:** Day-one load and exam length invite early abandonment. Placement is a single ~45-minute session in onboarding (F5, [04 §6.1]). A Sunday block is 45 minutes (35-40 min mock plus review), and the monthly mock is about 90 minutes in one sitting. That conflicts with R2/R6 (tiny, fixed tasks) and with the ADHD research. The level is already estimated (B1+ starting prior), so day 1 does not need a test.
   **Fix:** Use the initial level estimate as the prior (theta -0.3) and grant stage 3 provisionally on day 1. Split placement into 5-minute probes, one a day for the first week, inside the Daily Check slot. Allow the Weekly Mock as 3 sections of about 12 minutes on any 3 days Thursday-Sunday. Allow the Monthly Mock section by section within a 72-hour window, each section in its own Exam Mode attempt, with promotion requiring all sections CLEAN. Add test `PromotionTests/sectionedMockWithin72h`.

14. [medium] **Problem:** The plan ignores IELTS and leans on an Aptis guess for the exam family. TOEFL iBT and IELTS are the likelier targets. The plan shows only a TOEFL 1-6 scale, adds an Aptis-style block, and leaves out IELTS task types: Writing Task 2 opinion essay, and Speaking Part 2 cue card with 1 minute of preparation and a 2-minute long turn. The Part 2 long turn is the closest exam task to talking in meetings.
   **Fix:** In §7 Q2, lead with 'Did you mean TOEFL iBT?'. In F5/F7, show an IELTS-equivalent band beside the Tenaz band, mapped through CEFR and labelled 'approx.' [unverify the concordance against ETS/IELTS published tables]. Add IELTS Speaking Part 2 cue cards and a Task 2 essay to the Weekly and Monthly rotation as items in `Content/items`. Rename the Aptis block to 'Grammar & Vocabulary'.

15. [medium] **Problem:** Some milestone acceptances cannot be verified by an autonomous agent, or do not test what they claim. In M5, `--tenaz-probe-guard` is a separate process that prints and exits, so 'defaults write killSwitch → probe reports deny' never tests live KVO in the running app. M6 folds in spikes 1-2 (panel over a full-screen Space, which unlock notifications fire), which need a real lock/unlock and Screen Recording that an overnight agent does not have. M13 `build-data.py` depends on five live downloads.
   **Fix:** M5: the running app writes a heartbeat file `<AppSupport>/guard-state.json` (decision plus signals, every 2 s). Acceptance: start the app, `defaults write ... killSwitch -bool true`, then within 3 s guard-state.json shows `deny(killSwitch)`, then reset. M6: turn the spikes into an `--tenaz-spike-log` mode that records every unlock/wake/Space notification to a file; the learner locks and unlocks once in the morning, and that is the acceptance, not the agent's. M13: add `--offline` with checked-in small fixture extracts, so idempotency and licence tests run without network; the full download becomes a the learner item.

16. [medium] **Problem:** Several milestones are too large for one autonomous pass. M9 bundles the contract, penalties, repair flow, quests, achievements, mystery drop, 12 cosmetics, onboarding, weekly review and the experiment log. M12 bundles TTS, STT, fluency metrics, six speaking exercises, listening items, the Monthly Mock and promotion, and most of it cannot be tested overnight because mic permission is denied. M8 and M11 are also large. A failure in the middle leaves a half-built milestone and a tree that is hard to verify.
   **Fix:** Split M9 into M9a (Penalties, Contract with asymmetric delay, repair task, safety tests), M9b (quests, achievements, cosmetics, mystery drop) and M9c (onboarding with Arm Tenaz, weekly review, experiment log). Split M12 into M12a (TTS cache, listening items, typed-fallback Monthly Mock, median-of-3 grading, promotion) and M12b (SpeechAnalyzer, fluency metrics, 4/3/2, shadowing; acceptance on fixture transcripts, live mic as a the learner item). Each sub-milestone ends with its own `scripts/verify.sh` target and commit.

18. [medium] **Problem:** Penalties that are supposed to be off by default are on by default. F8 has 'missed daily minimum -10 Vitality' and decay, and F9 has 'missed day costs 20 Scales'. Neither is gated by the F10 Contract, although F10 says every penalty rule ships off. On a vacation week, Vitality drains to Sick and a repair task is waiting on return. R26 pauses penalties only on the first day back.
   **Fix:** Move both costs into the F10 cost table under 'Response cost' (off by default). When F10 is off, a missed day only changes Tena's mood (hungry or sad), with no meter loss. When it is on, after 2 missed days in a row the drain stops (a soft freeze) until the learner returns, and the welcome-back day restores 10 Vitality. Add tests `PenaltyTests/noDrainWhenResponseCostOff` and `PenaltyTests/drainStopsAfterTwoMissedDays`.

19. [medium] **Problem:** Tivra can quit Tenaz in the middle of an exam. §4.7 notes that a Tivra protection session with the learner's default list terminates Tenaz (only `com.chere3.focusflow*` is exempt), but the plan only lists it as a morning question. If it happens during a Monthly Mock, 90 minutes of work are lost, and the attempt may be treated as void or abandoned.
   **Fix:** In F5/M11: write `exam_response` per item as soon as it is answered. On relaunch, an attempt interrupted less than 15 minutes ago resumes, with the gap recorded in `pausedMs` and marked `integrity: interruptedByTivra` (not void). Preflight reads Tivra's `sessions` table read-only and warns 'a Tivra protection session is active and will close Tenaz' before starting. Add test `ExamTests/resumesAfterTermination`. Optionally, ask the learner about a bundle id under the exempt prefix (for example `com.chere3.focusflow.tenaz`), but first check that Tivra does not also exclude that prefix from capture (`frontExcluded`), because that would blind the witness.

20. [low] **Problem:** The menu-bar ruling conflicts with the timeline. F1's 20-second pre-announcement pulse is built in M6, but ruling 13 keeps `MenuBarExtra(.window)` and postpones the NSStatusItem decision to M14. MenuBarExtra has no API to open the popover programmatically or animate the item. On macOS 26 the item can also be hidden behind the notch or by the menu-bar visibility settings, and then the only warning is invisible.
   **Fix:** Move the NSStatusItem decision into M6 (or adopt NSStatusItem in M6 directly), with the pulse done as timed image swaps on `button.image`. Never rely on the menu bar alone for the pre-announcement: also play the soft tick and show a 20-second, non-key sticker 'Words in 20 s — Not now' bottom-right. Add test `OverlayTests/preannounceVisibleWithoutMenuBar` (coordinator emits the sticker event).

21. [low] **Problem:** The meeting calendar signal assumes work meetings are in EventKit. If the learner's work calendar (for example a corporate account that is not added to macOS) is not synced to this Mac, the calendar signal is empty. Meetings the learner joins muted on another device are then invisible, and the gate can appear right before a call.
   **Fix:** In M5, `--tenaz-probe-guard` lists the EventKit calendars with their event counts for today. Add a Settings choice for which calendars count as work. If none are work calendars, show 'Work meetings not visible' and offer a manual recurring 'meeting hours' schedule plus an ICS subscription URL field (read-only fetch). Add morning question: 'Are your work meetings in macOS Calendar?'
